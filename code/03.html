CODE 03

ファイルを
読ませる・書かせる

所要時間:約30分 レベル:基本 必要なもの:Claude Codeインストール済み
この回のゴール
  • ファイルの「読み取り」「書き込み」「編集」をClaudeに任せられる
  • 複数ファイルの一括処理ができる
  • 事故を防ぐ「Git」というバックアップ技を知る

1. ファイル操作はClaude Codeの十八番

Claude Codeが本領発揮するのは、ファイルを扱う時です。 アプリ版はファイルを1個1個渡す必要がありますが、Claude Codeはフォルダ全体を自由に読み書きできる。

ここをマスターすると、事務作業のほとんどが自動化できます。

2. 読み取り:まとめて読む

1つのファイルを読む

report.txtの中身を見せて。

複数ファイルを読む

このフォルダの.txtファイルを全部読んで、
どれが一番文字数多いか教えて。

PDFや画像も読める

このフォルダのPDF10個を読んで、
それぞれ3行要約を作って。

大量のファイル読み込み

100個以上の見積書PDFがこのフォルダにある。
全部読んで、金額の合計と、一番大きい案件を教えて。

Claudeが内部で順番に処理してくれます。大量でも大丈夫。

スクリーンショット:大量のPDFを読み込んで集計している様子

3. 書き込み:新しくファイルを作る

新規に「nisshi.md」というファイルを作って、
今日の日記テンプレートを入れて。

内容:
- 日付(今日の日付)
- 今日やったこと
- 気づき
- 明日やること

空欄で書いておいて。

.mdは「マークダウン」という、軽い文書フォーマット。 メモ代わりに使いやすい形式です。

プロジェクト一式を作る

「my_website」というフォルダを作って、
その中に、シンプルなホームページ一式を作って。

- index.html(トップページ)
- style.css(見た目)
- profile.html(自己紹介)

内容は仮で、あとから自分で書き換える想定。

Claudeがフォルダとファイルをまとめて作成してくれます。

4. 編集:既存ファイルを書き換える

1箇所だけ直す

profile.html の「hello」を「こんにちは」に変えて。

全体を書き換える

report.txtを読んで、文章を整えて書き直して。
誤字脱字を直して、改行を見やすく調整。

複数ファイル一括で

このフォルダの.htmlファイル全部で、
「copyright 2024」を「copyright 2026」に置き換えて。

5. 事故防止:Gitを使ってバックアップ

Claudeに大きな書き換えを任せる前に、必ずバックアップを取ってください。 おすすめはGit(ギット)という仕組みを使う方法。

Gitって何?

Gitは「ファイルの歴史を記録してくれるタイムマシン」みたいな仕組み。 Claudeが変なことをしても、前の状態にいつでも戻せる。

Gitの使い方(最低限)

Claudeに聞けば全部やってくれます。

このフォルダをGit管理下にして。
「最初の状態」としてコミットを1つ作って。

こう頼めば、バックアップの起点ができます。

大きな作業の後は:

今の状態を「◯◯の変更完了」としてコミットして。

万が一、変な風に書き換わったら:

さっきの変更を全部取り消して、前のコミットに戻して。
Gitは最初ちょっと難しいですが、「前に戻れる」安心感は絶大。 Claudeに教えてもらいながら使えば、数日で慣れます。

6. 使える実例5選

例1:フォルダのファイル名を一括変更

このフォルダにある画像ファイルを、
「2026年04月24日_1.jpg」のような形式にリネームして。
日付は撮影日、連番は撮影順で。

例2:テキストの集計

「logs」フォルダの中の.txtファイルを全部読んで、
エラーメッセージだけ抽出して、error_summary.csvにまとめて。

例3:文書の置換

docs/ フォルダの中にある.mdファイル全部で、
「ABC株式会社」を「XYZ合同会社」に置き換えて。

ただし、表紙ファイル(cover.md)だけは置き換えないで。

例4:CSVの整形

顧客リスト.csvを読み込んで、
メールアドレスが重複している行を削除して、
新しくclean.csvとして保存して。

例5:画像の整理

photos/ フォルダの画像を撮影日別にサブフォルダに分類して。
例:「2026-01」「2026-02」...みたいな月別フォルダで。

7. よくあるミスと対策

ミス1:意図と違うファイルを書き換えられた

対策:先に手順を聞く。「これから何をするか」を先に答えてもらい、OK出してから実行。

ミス2:バックアップ無しで実行して後悔

対策:必ずGitでコミットしてから作業。またはフォルダを丸ごとコピーしてから。

ミス3:大量のファイルを一気に処理させたら想定外のものまで処理された

対策:「まず1〜2個でテスト」してから全部に広げる。 

全ファイル処理する前に、まず1つだけでテスト処理して、
結果を見せて。問題なければ、残り全部に広げる。

8. やってみよう

  1. 練習フォルダを1つ作る
  2. その中にテキストファイルを5つ、中身を適当に書いて作る
  3. Claude Codeで次を順番に依頼:
    • フォルダの中身を一覧にして
    • 5つのファイルの中身を全部連結して、まとめ.txtを作って
    • まとめ.txtの文字数を教えて
    • 5つのファイルを「backup/」サブフォルダに移動して
  4. 各ステップで、どう動いたかを観察する
このLESSONの内容が身につけば、日常の事務作業の半分以上が時短できます。 あとは繰り返し使って、自分の仕事に馴染ませるだけ。
この回のまとめ
  • ファイル操作(読み/書き/編集)は、Claude Codeの得意分野
  • 大きな変更の前は必ずバックアップ(Git or フォルダコピー)
  • 「先に手順を見せて」「まず1つでテスト」で事故防止
  • 慣れれば、事務作業が一気に自動化できる
