CODE 05

自分用に
カスタマイズ

所要時間:約30分 レベル:応用 必要なもの:Claude Codeインストール済み
この回のゴール
  • Claudeに「自分の流儀」を覚えさせる方法が分かる
  • 「CLAUDE.md」という設定ファイルを書ける
  • プロジェクトごとの好みを毎回指示し直さなくて済む

1. 「CLAUDE.md」って何?

アプリ編のLESSON 03で学んだ「プロジェクトのカスタム指示」、覚えてますか? 「このプロジェクトでは毎回こういう前提で動いて」と伝えておく、アレです。

Claude Codeにも、同じ仕組みがあります。それが「CLAUDE.md(クロード・ドット・エムディー)」というファイル。

普通のフォルダ = Claudeは毎回「はじめまして」
CLAUDE.mdあるフォルダ = Claudeが毎回「いつもの前提で」動く

何が書ける?

  • プロジェクトの目的・背景
  • 使ってるツール・ライブラリ
  • コードの書き方のルール
  • やってほしくないこと
  • 自分の好み(日本語で返事して、など)

2. 作り方(一番シンプルな例)

手順

  1. プロジェクトのフォルダに移動
  2. そこにCLAUDE.mdというファイルを作る
  3. 中に、Claudeに伝えたいことを書く
  4. 次回からClaudeが自動で読んでくれる

Claudeに作らせるのが早い

このフォルダにCLAUDE.mdを作って。

内容:
- このプロジェクトは「家計簿アプリ」の開発
- Python + SQLiteで作る
- 日本語で会話して
- コメントも日本語で書いて
- テストを先に書くスタイルで進めたい

Claudeがその場で CLAUDE.md を作ってくれます。

3. CLAUDE.mdの書き方テンプレート

迷ったら、この型をコピペしてカスタマイズ。

# プロジェクト:◯◯

## プロジェクトの目的
- 何を作るか・誰のために・何のために

## 使っている技術
- 言語:Python 3.11
- フレームワーク:◯◯
- データ保存:◯◯

## コードの方針
- シンプルに書く
- 関数は短く、1つのことだけをする
- コメントは日本語で

## 進め方
- テストを先に書く(TDD)
- 変更はGitでコミットしてから

## 避けてほしいこと
- 推測で動かない。不明なことは質問してから進める
- 大量のファイル変更を一度にしない

## 会話のトーン
- 日本語で
- 丁寧すぎず、フランクに

4. 階層で使い分けできる

CLAUDE.mdは、フォルダごとに置けます。 Claudeは、今いるフォルダから順番に、親フォルダまで全部読みに行きます。

例:階層構造

~/
├── CLAUDE.md          ← 全体共通の好み
└── Desktop/
    ├── project_A/
    │   ├── CLAUDE.md  ← プロジェクトA固有の指示
    │   └── src/
    └── project_B/
        └── CLAUDE.md  ← プロジェクトB固有の指示

ホーム直下のCLAUDE.mdに書くべきこと

  • 自分の名前・役割(例:「フリーランスのエンジニア」)
  • 全プロジェクト共通のルール(日本語で会話、丁寧に等)
  • 自分の得意・苦手(専門用語レベル、経験年数)

プロジェクト直下のCLAUDE.mdに書くべきこと

  • そのプロジェクトの目的
  • 使ってる技術・ライブラリ
  • ファイル構成の説明
  • このプロジェクト特有の注意点

5. 実践:実際に作ってみる

例1:ライター向け

# 私について
- 職業:Webライター
- 専門分野:ビジネス、副業、キャリア
- 文字数相場:3000〜5000字/記事

# お願い
- 原稿作成は、タイトル → 見出し → 本文 の順で進める
- 一度に書きすぎない。見出しごとに確認を入れる
- 誤字チェックは最後にまとめて

# 文体
- です・ます調
- 専門用語は初出時に補足
- 断定は控えめ、根拠を添える

# 禁止事項
- 出典を捏造しない
- 数字は必ず根拠を確認

例2:営業職向け

# 私について
- 職業:法人営業(BtoB)
- 扱い:中小企業向けSaaS
- 担当:関東エリア

# お願い
- メール文面は、丁寧・簡潔・信頼感の3点重視
- 営業トークは、相手の課題に寄り添う形で
- 数字や実績は、根拠と出典セットで

# 禁止事項
- 誇大な表現
- 競合の悪口
- 個人情報の取り扱い注意

例3:個人事業主向け

# 私について
- フリーランスのデザイナー
- 得意:紙・Web両方
- ツール:Adobe系、Figma

# 仕事の進め方
- 見積もりは詳細に(工数+内容)
- 先方とのやりとりはメール中心
- 納品前に必ず自己レビュー

# お願い
- 提案書は、相手のロゴ・社風に合わせて丁寧に
- 見積書は、他社比較されても困らない明朗会計で

6. 活用のコツ

コツ1:使いながら育てる

最初から完璧にしようとしない。 「あ、毎回これ指示してるな」と気づいたら、CLAUDE.mdに追記。 使うほど、だんだん最強のCLAUDE.mdになります。

コツ2:短く、具体的に

長すぎると読んでもらえないし、抽象的すぎると伝わりません。 箇条書き・1項目1行が基本。

コツ3:「禁止事項」をちゃんと書く

「やってほしいこと」より「やってほしくないこと」の方が、地雷を避けやすい。 「機密情報を外部に送信しない」「勝手にライブラリを入れない」など、明確に書いておきましょう。

7. CLAUDE.mdの仲間たち

より細かくカスタマイズしたい人向けに、Claude Codeには他にも設定の仕組みがあります。

  • .claude/settings.json:もっと細かい動作設定(許可コマンドなど)
  • .claude/commands/:自分だけのショートカット作成(次回のLESSON 06で扱う)
  • .claude/agents/:専門家キャラを作れる(同じく次回)

今回のCLAUDE.mdだけでも、かなり快適になります。 余裕が出てきたら、次の仕組みにも手を伸ばしてみてください。

8. やってみよう

  1. 自分のメイン作業フォルダに移動
  2. Claudeに「CLAUDE.md作って」と頼む(上のテンプレ参考に)
  3. 作ったあと、何か作業を1つ頼んでみる
  4. 「いつもと違う、馴染んだ感じ」を味わう
  5. 気になる箇所があれば、CLAUDE.mdを編集して調整
CLAUDE.mdを育てるのは、「Claudeを自分専用の助手にする作業」。 使い込むほど、仕事の相棒度が上がります。
