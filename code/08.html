この回のゴール
  • Claudeが「自動で動く」仕組みを3種類理解する

1. ついに「自分が何もしなくても動く」段階へ

ここまでの7回で、Claudeに話しかけて動かす方法を学びました。 最後のこの回では、放置しても勝手に動く仕組みを紹介します。

例えば:

  • 毎朝9時に、今日のニュース+天気+ToDoを自動で整理してくれる
  • 新しいメールが届くと、自動で返信の下書きを作ってくれる
  • 毎週金曜日に、今週の振り返りレポートを自動生成
  • コードを保存するたびに、自動でテストを実行

これらは全部、Claude Codeで実現できます。

2. 自動化の3パターン

パターン1:時間を決めて動かす(スケジュール実行)

「毎朝9時に」「毎週月曜に」のように、時間指定で動かす方法。

主な使い方:

  • 朝のルーティン実行
  • 週次・月次の定期レポート
  • バックアップ

パターン2:何かが起きたら動かす(イベント駆動)

「ファイルが保存されたら」「メールが来たら」のように、トリガー(きっかけ)で動かす方法。 Claude Codeではこれを「フック(Hook)」と呼びます。

主な使い方:

  • ファイル保存時に自動テスト
  • コード編集時に自動フォーマット
  • Git操作の前後に検証

パターン3:連続で動き続ける(ループ実行)

ずっと動き続けて、状況が変わるたびに対応する方法。

主な使い方:

  • 新着メッセージの監視・対応
  • ログの監視・アラート
  • 定期的なWebサイトの更新チェック

3. スケジュール実行のやり方

Claudeに頼んで作ってもらう

毎朝9時に、以下を自動でやる仕組みを作って。

1. 今日の天気を取得(東京)
2. 今日のカレンダー予定を一覧化
3. 未読メールの件数確認
4. ToDoリストを優先度順に
5. 上記をまとめて、daily_briefing_2026-04-24.md に保存

実行環境:MacのLaunchd、または Windowsタスクスケジューラ

必要な準備と、手順を教えて。

Claudeが仕組みを作って、設定手順まで案内してくれます。

使える仕組み(OSごと)

  • Mac:launchd または cron
  • Windows:タスクスケジューラ
  • Linux:cron

名前は違いますが、どれも「決まった時刻に、決まった処理を実行する」ための標準機能です。

4. フック(Hook)の使い方

フックは、Claude Code内の特定の操作の前後に、自動で何かを実行する機能。

使える主なフック

  • PreToolUse:ツール実行前に動く
  • PostToolUse:ツール実行後に動く
  • SessionStart:セッション開始時に動く
  • Stop:セッション終了時に動く

実例:ファイル保存時に自動フォーマット

Claude Codeでファイルを書き込んだ後、
自動で「prettier(自動整形ツール)」を走らせたい。

~/.claude/settings.json にフックを設定して。

これで、Claudeがファイル書き込みをするたびに、自動で整形してくれます。

実例:コミット前に自動テスト

Git commit前に、自動でテストを走らせて、
失敗したらコミットを止める仕組み作って。

  2. 週次振り返り:金曜17時に今週のGitHub活動をまとめ

6. 始める前に決めておくこと

1. 本当に自動化する必要があるか?

「週1回の作業」なら、自動化の手間が割に合わない。 週3回以上、または頻繁にミスする作業だけ自動化の対象にしましょう。

2. 失敗時の対処を決めておく

自動化したものは、失敗する可能性が必ずあります。 「失敗したらメール通知」「失敗したら前回のバックアップに戻す」など、事前に決めておく。

3. 定期的に点検する

「気づいたら3ヶ月動いてなかった」はよくある話。 月1回くらい、自動化が正常に動いてるか確認する習慣を。

7. 自動化のやり過ぎに注意

自動化は強力だが、暴走すると怖い。 「毎日全メールに自動返信」みたいな設定でトラブルが起きると、止めるまで被害が続きます。

避けるべき設定

  • 確認なしで他人にメール送信する設定
  • 確認なしで大量削除する設定
  • ループで無限に動き続ける設定(お金・リソース食いつぶし)
  • 権限が強すぎるAPIキーでの自動実行

安全にする工夫

  • まず「下書き保存」や「通知」止まりにする
  • 本番環境の変更は、必ず人間の承認を挟む
  • 実行回数・時間・対象を明確に制限する
  • 定期的にログをチェック
